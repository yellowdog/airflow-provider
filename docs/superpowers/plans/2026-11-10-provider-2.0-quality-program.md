# YellowDog Airflow Provider 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the provider into a fully tested, type-checked, CI-gated, well-documented Airflow-3-only 2.0.0 release with a local release script.

**Architecture:** Keep the existing module layout (`hooks/`, `operators/`, `sensors/`, `utils/`, `exceptions/`). Add a small typed templating layer (`utils/templating.py`) so every "value or callable" field resolves through one checked function instead of `cast()`. Unit tests mock `PlatformClient`; system tests (opt-in, real platform) live under `tests/system/` and share one TOML config. Tooling is driven from the `Makefile`; CI calls the same targets.

**Tech Stack:** Python 3.12–3.14, Apache Airflow ≥ 3.1 (`airflow.sdk`), yellowdog-sdk, pytest, ruff, pyright, Sphinx + sphinx-rtd-theme, GitHub Actions, Docker (e2e + docs image), twine.

**Spec:** `docs/superpowers/specs/2026-11-10-provider-2.0-quality-program-design.md`

## Global Constraints

- `apache-airflow >= 3.1`; `requires-python = ">=3.12, <3.15"`; classifiers 3.12, 3.13, 3.14. (Raised from 3.10 during Task 11: on Python < 3.12 every `yellowdog-sdk` release caps `urllib3<2`, which conflicts with Airflow's constraints files, so the provider cannot be installed the recommended way on 3.10/3.11. Python 3.10 is EOL as of 2026-10.)
- All Airflow imports from Airflow 3 locations — `from airflow.sdk import BaseHook, BaseOperator, BaseSensorOperator, Connection, Context, TaskInstance, TriggerRule, dag`. No `try/except ImportError` fallbacks, no `# type: ignore[no-redef]`.
- Test matrix (verified on PyPI 2026-11-10: Airflow 3.1.0 supports 3.10–3.13; latest 3.4.0 supports 3.11–3.14): **min Airflow (3.1.0) × Python {3.12, 3.13}** and **latest Airflow × Python {3.12, 3.14}**. CI installs with uv.
- Version string during development: `2.0.0.dev0`; set to `2.0.0` only at release time.
- Changelog for 2.0.0 is relative to **1.0.4** (1.0.5 never released, skipped).
- Breaking changes: every one gets a before/after entry in `docs/changelog.rst` → "Migrating from 1.x".
- Do not catch SDK exceptions (except existing YEL-13327 idempotent-cancel tolerance). No JSON/dict wrappers around SDK objects. No object store support.
- Plain `pytest` and CI must never touch the YellowDog platform.
- Do not touch the untracked `dag-test.py`. No `CONTRIBUTING.md`.
- No generated `.pyi` stubs; ship `py.typed`; `pyright --verifytypes` must report 100% known exported symbols.
- Run `make format` after every Python change (user preference).

## Review Focus

1. **Templated ID renders to `"None"` or `""`** — e.g. `"{{ ti.xcom_pull(task_ids='x') }}"` in an `ALL_DONE` teardown when upstream failed. Expected: a `YellowDogArgumentError` naming the field and suggesting the upstream XCom is missing, not a confusing platform 404. → Task 5.
2. **User callable with wrong parameter names** (`def gen(ctx, env)`): Airflow calls callables as `value(context=..., jinja_env=...)`, so this fails at render time. Expected: pyright flags it in the user's DAG via the `TemplateCallable` protocol, and docs state the required names. → Task 3.
3. **Release with untracked local files** (`dag-test.py` is permanently untracked): expected to proceed; tracked modifications must block. → Task 15.
4. **System test interrupted after provisioning** (Ctrl-C, crash): expected no orphaned pools/compute; leftovers identifiable by run tag and removable with one command. → Tasks 12, 14.
5. **Connection host without scheme or with path/trailing slash** (`api.yellowdog.ai`, `https://test.yellowdog.tech/api/`, URI-form connections): expected to work — prepend `https://` when no scheme, strip trailing `/`. → Task 4.

**Interfaces:**
- Produces:
  ```python
  class YellowDogException(Exception): ...           # base, unchanged name
  class YellowDogArgumentError(YellowDogException, ValueError): ...

  T_co = TypeVar("T_co", covariant=True)
  class TemplateCallable(Protocol[T_co]):
      def __call__(self, *, context: Context, jinja_env: Environment) -> T_co: ...
  Templated: TypeAlias = "T | TemplateCallable[T]"   # generic alias over T

  def resolve(value: Templated[T], field_name: str) -> T
  def resolve_optional_str(value: Templated[str] | None, field_name: str) -> str | None
  ```
- `resolve`: if `callable(value)` raise `YellowDogException(f"Templated field '{field_name}' has not been rendered; ...")`; else return it.
- `resolve_optional_str`: `None` or `""` (after `.strip()`) → `None`; the literal `"None"` → raise `YellowDogArgumentError` whose message contains the field name and `"upstream XCom"`; otherwise the stripped string.
