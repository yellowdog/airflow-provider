# Teardown Scope Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** By default, `ShutdownProvisionedWorkerPool` cancels only the unfinished work requirements submitted by tasks in its own setup/teardown scope, not by every task in the DAG run.

**Architecture:** The task digest in the run-stamp tag no longer covers the map index, which becomes its own tag part. That lets a teardown filter the run's unfinished work requirements by the task digests of the tasks in its scope. It finds its scope at run time by walking its own DAG: its setups, plus every task that is downstream of a setup and upstream of the teardown. A three-way parameter replaces the boolean.

**Tech Stack:** Python 3.12–3.14, Airflow 3.1–3.4 (`airflow.sdk`), yellowdog-sdk ≥ 15.10.0, pytest, pyright strict, Sphinx.

**Spec:** the design was approved in chat on 2026-11-11; it is restated under "Design" below. It extends `docs/superpowers/specs/2026-11-11-provider-2.0-workflow-design.md`, which is otherwise unchanged.

## Design (approved)

- **Problem:** with `cancel_run_work_requirements=True` (the default), a teardown aborts every unfinished work requirement in its DAG run. That includes work in parallel branches: another pool's setup/teardown scope, or a `RunWorkRequirement` on an existing pool. The other task then fails as CANCELLED.
- **Tag format (2.0 is unreleased, so the change costs nothing):**
  - Before: `airflow:<run digest>:<task digest(task_id, map_index)>:c<cycle>`.
  - After: `airflow:<run digest>:<task digest(task_id)>:m<map_index>:c<cycle>`. The map index of an unmapped task is `-1`, giving `m-1`.
  - The deployment ID stays mixed into both digests, as now.
- **Parameter:** `cancel_work_requirements: Literal["scope", "run", "none"] = "scope"` replaces `cancel_run_work_requirements: bool`. Any other value raises `YellowDogArgumentError` at construction, so at DAG parse time.
  - `"scope"`: cancel the unfinished work requirements of tasks in this teardown's scope.
  - `"run"`: today's behaviour, the whole DAG run.
  - `"none"`: cancel nothing.
- **Scope** is the task IDs of:
  - the teardown's setups: its direct upstream tasks with `is_setup`;
  - every task that is downstream of any of those setups (`get_flat_relatives(upstream=False)`) and upstream of the teardown (`get_flat_relatives(upstream=True)`).
  - The teardown itself is excluded. Mapped tasks are covered by task ID, so every map index is included.
  - Checked on Airflow 3.1.0 and 3.4.0 with a parsed DAG holding two parallel scopes: each teardown's scope was exactly its own branch.
- **No scope:** if the teardown is not `is_teardown`, or has no setups, `"scope"` cancels nothing and logs a warning saying so, which points to `"run"`.
- **Out-of-scope tasks** (for example a `RunWorkRequirement` on an existing pool) are no longer swept by any teardown under `"scope"`. They still cancel their own work on failure, timeout or kill; the only thing lost is cleanup after a worker crash. The docs say this and point to `"run"`.
- **Unchanged:** the teardown's other behaviour and order (it cancels before shutting the pool down, best effort, failures logged and never raised); searching all namespaces; the run-prefix format guard.

## Global Constraints

- Run `make format` after Python changes. `make check` must pass. Also run the unit tests and `pyright yellowdog_provider` with `.venv-systest-min` (Airflow 3.1).
- pyright strict; operator arguments are keyword-only; SDK exceptions are not caught in operators, except the existing best-effort cancel paths.
- Never run live tests (the controller runs them). Never touch `dag-test.py`, `CLAUDE.md`, `tests/system/config.toml` or `userdata.sh`.
- Name rules (`NAME_PATTERN`) and `derive_name` are unchanged. Names do not depend on the tag format.

## Review Focus

1. A mapped task in scope: every map index's work requirement is cancelled by the scoped teardown.
2. Retry and resume: ownership (`_owned_cycle`) must still match exactly. The tag of map index 1 must never match map index 12 (`m1` vs `m12`), with or without `:c<n>`.
3. A task in two overlapping scopes is cancelled by whichever teardown runs first. That is correct, and must not raise.
4. A teardown inside an Airflow TaskGroup: task IDs are fully qualified (`group.task`), and their digests must match the stamps that the submitting tasks wrote.
5. `"scope"` on an operator that is not a teardown, or has no setups: warns and cancels nothing, and never fails the task.

### Task 1: Tag format and scoped lookup (run stamp and hook)

**Files:**
- Modify: `yellowdog_provider/utils/run_stamp.py`
- Modify: `yellowdog_provider/hooks/yellowdog_hooks.py` (`attempt_tag`, `_owned_cycle` docs, `find_unfinished_run_work_requirements`)
- Test: `tests/unit/utils/test_run_stamp.py` (or wherever the run-stamp tests live), `tests/unit/hooks/test_hook_operations.py`

**Interfaces:**
- Produces:
  - `RunStamp.task_tag_prefix() -> str`: `f"{run_tag_prefix()}:{_digest(*deployment, task_id)}"`.
  - `RunStamp.tag() -> str`: `f"{task_tag_prefix()}:m{map_index}"`.
  - `task_tag_prefix_for(stamp: RunStamp, task_id: str) -> str`, a module function in `run_stamp`: the task tag prefix of another task in the same DAG run (the same dag_id, run_id and deployment_id). Equivalent to `dataclasses.replace(stamp, task_id=task_id, map_index=-1).task_tag_prefix()`.
  - `TASK_TAG_PREFIX_PATTERN`: fullmatches `airflow:<12hex>:<12hex>`.
  - `YellowDogHook.find_unfinished_run_work_requirements(namespace: str | None, run_tag_prefix: str, task_tag_prefixes: Collection[str] | None = None) -> list[str]`.
    - With `None`, behaviour is as now.
    - With a collection, it returns only work requirements whose tag starts with `<one of task_tag_prefixes>:`.
    - It raises `YellowDogArgumentError` if any task prefix does not fullmatch `TASK_TAG_PREFIX_PATTERN`, or does not start with `run_tag_prefix + ":"`.
    - An empty collection returns `[]` without calling the platform.

- [ ] **Step 1: Write failing tests**
  - `tag()` has the form `airflow:<12hex>:<12hex>:m<index>`, with `m-1` for an unmapped task.
  - Two map indices of one task share `task_tag_prefix()`; two task IDs do not.
  - A non-empty `deployment_id` changes `task_tag_prefix()`.
  - `task_tag_prefix_for(stamp, "other")` equals the stamp built with `task_id="other"`.
  - `_owned_cycle` (`m1` against `m12`): the tag `...:m12:c3` is not owned by the stamp with `m1`, and `...:m1:c3` is owned.
  - `find_unfinished_run_work_requirements` with task prefixes:
    - filters correctly when given mixed summaries: in scope, other task, other run, finished;
    - an empty collection makes no platform call;
    - a malformed prefix, or a prefix from another run, raises.
- [ ] **Step 2: Run the tests to check they fail.** Run `pytest tests/unit -q -k "run_stamp or unfinished or owned"`; the new tests should fail.
- [ ] **Step 3: Implement as in Interfaces.**
  - Update every docstring that states the tag format, including the `submit_work_requirement` and `attempt_tag` docs.
  - Search the package for other code that builds or parses tags (`grep -rn "tag()" yellowdog_provider tests`), and update test fixtures that hard-code the old format.
- [ ] **Step 4: Check the results.** `pytest tests/unit -q` passes, and so does `make check`.
